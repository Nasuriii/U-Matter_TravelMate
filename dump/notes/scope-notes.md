# Mission 4 scope notes

- Mission 1 listed passwords/custom sessions; the professor-directed Mission 3
  implementation uses Google OAuth, Supabase Auth, public UUID profiles and role
  junctions. Keep this approved evolution documented.
- Mission 1 Process 6 requires verified online payments/receipts. A sandbox payment
  integration is proposed, subject to instructor acceptance. A browser-generated
  paid flag is not verified payment. This batch contains no payment feature.
- The overview mentions transport bookings, but Process 10 describes provider
  and service listing management. Resolve before adding transport reservations.
- Search/filter is included. Algorithmic recommendations and schedule optimization
  in Process 8 are not implemented in Batch 1.
- PostgreSQL job roles and authenticated Google app roles are distinct.
  Later security work must map reviewer/analyst responsibilities deliberately.
- Prototype visual language is reused; this first batch is not a pixel-for-pixel
  conversion of all 8,573 lines or all prototype screens.
